# 歷史實車調校與效能紀錄

記錄日期：2026-09-23。來源為專題使用者對先前實車測試的補充與回憶，並非此次整理時重新量測。

## 車輛與參數狀態

車輛已拆除，許多尺寸、接線及運轉資料無法重新量測。使用者說明，大部分程式參數曾依實車情況調整校正，因此本專案保留原有部署數值，作為當時工程實作的紀錄。個別參數的校正步驟、前後對照與量測日誌未完整留存，不將這項整體說明擴大為每一個數值皆已獨立驗證。

輪徑、輪距與模型尺寸的差異，可同時保留「實體標稱尺寸」「程式部署值」「模型表示值」；不僅因數字不同就判定部署值錯誤，也不以標稱尺寸直接覆寫原程式。編碼器倍率的條件式推算、footprint 軸向等靜態對照則保留為歷史差異，供日後重建參考，不能回推當時必然發生特定程度的誤差。

## 可寫入報告的效能資訊

| 項目 | 歷史回報 | 證據與表述範圍 |
|---|---|---|
| 點雲 topic 發布頻率 | 約 3.75 Hz | 使用者對先前實車測試的回憶；主流程點雲 topic 為 `/ouster/points`。未保留當次量測指令、時間窗與原始日誌。 |
| 車輛辨識更新率 | 平均高於 1 Hz | 使用者記得約 1 或 1.5 Hz，但無法確定精確值。正式摘要採「平均高於 1 Hz」；不把 1.5 Hz 寫成確定平均，也不把 1–1.5 Hz 當成實測上下界。 |
| 里程計／NDT／Nav2 | 程式設定分別為 50／10／5 Hz | 屬計時器或設定頻率，沒有對應的歷史實測數值。Mega 計數回報約 20 Hz 等級亦來自韌體時序推算。 |
| 延遲、負載與品質指標 | 未留存完整數據 | 沒有可核對的端到端延遲、CPU/GPU 負載、定位誤差、辨識準確率或導航成功率紀錄。 |

辨識的量測口徑未留存，不能確定當時觀察的是推論完成頻率或某一輸出 topic 頻率。上述資訊適合作為歷史運行概況，不是固定硬體條件下可重現的 benchmark，也不能只由這兩個頻率定位效能瓶頸。`sync_time_stamp=true` 會改寫點雲 callback 的時間戳，亦不能據此補算當時的感測端到端延遲。

建議報告文字：

> 系統參數多依當時實車運行情況進行調整。依團隊對先前實車測試的回報，點雲 topic 發布頻率約為 3.75 Hz，車輛辨識平均更新率高於 1 Hz。由於車輛現已拆除，且目前未取得完整原始量測日誌，上述數值為歷史測試的近似紀錄，無法重新驗證精確平均值與波動範圍。

## 地圖場景的歷史說明

使用者已確認曾有室內與室外地圖，並補充室外測試時車輛無法移動；修改相關檔名後仍未解決，當時未找到原因。使用者進一步確認 `mymap.yaml` 與 `my_map.yaml` 是兩個不同場地的地圖；各自對應室內或室外尚未明示。已找到 [run.md](../fish/ros2_ws/run.md) 的操作順序，Nav2 先於 GUI 及 map.sh 啟動。因此 Foxy 地圖訂閱覆寫雖仍是設定問題，「晚加入漏收」已降為備選。操作紀錄沒有各節點就緒時間，不能替代當次實車日誌。完整結論與證據強度見 [室外導航調查](室外導航無法移動_調查報告.md)，設定對照見 [CONFIGURATION](CONFIGURATION.md)。
